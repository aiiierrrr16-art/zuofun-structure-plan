06 · IMPLEMENTATION

前台整合，后台继续分工。

页面结构优化不要求把所有内容做成同一种后台对象。正确方式是由URL识别内容类型，再调用对应内容与模板。

用户访问URL页眉、正文、搜索或页脚入口
→
WordPress识别Page / Post / Product / Category
→
调用内容Elementor / Post / WooCommerce
→
套用模板The7 / Product / Archive
→
注入SEORank Math metadata
对象负责内容实施要求
Pages / Elementor首页、品类、服务、About、Contact页面级结构与模块编辑
WooCommerce Products141个产品数据统一详情模板，不写死数据
Product Categories33个产品分类统一归档模板，清理空分类入口
Posts163篇文章统一文章模板和内容分类
Menu标签、层级、目标URL与页面内容和SEO字段分开管理
Rank MathTitle、Description、Canonical、Schema按页面类型配置，不控制视觉结构
07 · ROADMAP

实施顺序与验收标准。

先排除会影响抓取、询盘和核心入口的问题，再实施结构与视觉。每一阶段都应有URL、桌面端、移动端和后台维护验收。

第一阶段
修复基础风险
Sitemap、SMTP、/product/、Banner失效链接；保留修复证据。
第二阶段
确认结构和URL
页眉、页脚、首页模块、新旧URL映射、缺失页面决策。
第三阶段
核心页面改造
首页、四个品类页、Services、About、Contact、News。
第四阶段
模板改造
Products归档、产品详情、分类归档、文章列表与详情。
第五阶段
内容治理与SEO验收
FAQ、重复页面、空分类、301、Title/H1/Canonical/Schema与GSC提交。

验收清单

页眉与页脚每个菜单项均有明确有效URL
原重要URL保留或一对一正确301
桌面与手机端菜单均可使用
固定Banner两个分流按钮目标正确
四种合作模式不再依赖自动轮播
Products分类无需点击“+”才能理解
产品与文章由全局模板调用真实数据
询盘提交后公司邮箱实际收到完整内容
Sitemap与核心页面返回正确HTTP状态
Title、H1、Canonical与Schema符合页面类型
上线后无新增404和孤立核心页
19个FAQ有明确保留、内链、合并或noindex决策
